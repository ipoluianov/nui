# Тестирование nui и приложений на nui

Есть четыре инструмента:

| Инструмент | Что проверяет | Запуск |
|---|---|---|
| `ui/uitest` | формы без дисплея: клики, ввод, меню, диалоги, эталонные картинки | `go test ./...` |
| `ui/regression` | известные баги библиотеки: тест пропускается, пока баг есть, и падает, когда баг исправлен | `go test ./ui/regression -v` |
| `ui/benchmarks` | производительность: TextBox, таблица, раскладка, отрисовка | `go test ./ui/benchmarks -run xxx -bench . -benchmem` |
| `scripts/check-clients.sh` | что соседние приложения на nui собираются и проходят свои тесты с текущей рабочей копией nui | `scripts/check-clients.sh` |

## uitest: тесты форм без дисплея

Импорт `github.com/ipoluianov/nui/ui/uitest` переводит весь тестовый бинарник в headless-режим:
- окна существуют только в памяти, на экране ничего не появляется;
- дисплей не нужен, работает в CI и по SSH;
- поддерживаются Linux, Windows и macOS.

Тест показывает форму, действует как пользователь и проверяет либо состояние виджетов, либо картинку:

```go
func TestEditing(t *testing.T) {
	n := newNotepad()
	w := uitest.Show(t, n.form)        // форма закроется в конце теста

	w.Shortcut("Mod+A")                // Cmd на macOS, Ctrl на остальных
	w.Type("hello world")
	w.Click(w.Find("Edit"))            // пункт главного меню по тексту
	w.Click(w.Find("Upper Case"))      // пункт открытого меню

	if got := n.text.Text(); got != "HELLO WORLD" {
		t.Errorf("text = %q", got)
	}
	w.MatchGolden("notepad-upper")     // сравнение с testdata/golden/notepad-upper.png
}
```

Рабочий пример — [examples/notepad/notepad_ui_test.go](../examples/notepad/notepad_ui_test.go), возможности по отдельности показаны в [ui/uitest/uitest_test.go](../ui/uitest/uitest_test.go).

### Что умеет `Window`

| Группа | Методы |
|---|---|
| Мышь | `Click`, `RightClick`, `DoubleClick`, `Drag(from, to)`, `Move`, `Press`/`Release`, `Wheel(at, dx, dy)`, `DropFiles(at, files...)` |
| Клавиатура | `Type("text\n")`, `Key(ui.KeyF5, mods)`, `Shortcut("Ctrl+Shift+S")` |
| Поиск виджетов | `Find("имя или текст")`, `FindAll(func)`, `Focused()`, `Popup()` |
| Окна | `Dialog()` — модальное окно поверх формы, `Top()` — последнее открытое окно, `Blocked()`, `Closed()`, `Title()`, `RequestClose()` — щелчок по крестику, `Resize` |
| Время | `Settle()` — выполнить отложенные `Invoke`, `Tick()` — одно срабатывание таймеров, `Wait(d)` — подождать с работающими таймерами |
| Картинки | `Screenshot()`, `MatchGolden(name)` |

Цель действия задаётся одним из двух способов:
- **виджетом** — тогда действие происходит в его центре;
- **точкой** `uitest.At(widget, dx, dy)` или `uitest.Point{X, Y}` в координатах окна.

### Эталонные картинки

`MatchGolden("name")` сравнивает снимок окна с `testdata/golden/name.png` в пакете теста.

- **Эталона ещё нет.** Тест записывает его и падает. Нужно посмотреть на картинку и запустить тест снова.
- **Есть расхождение.** Рядом с эталоном появляются `name.actual.png` — что получилось — и `name.diff.png` — отличия, закрашенные красным.
- **Перезаписать эталоны:** `go test ./pkg -update-golden` или `NUI_UPDATE_GOLDEN=1 go test ./pkg`. Перед коммитом новые картинки нужно просмотреть: с этого момента тест ожидает именно их.
- **Допуски.** `uitest.GoldenTolerance` — насколько может отличаться канал пикселя, по умолчанию 8 из 255. `uitest.GoldenMaxDiff` — какая доля пикселей может отличаться, по умолчанию 0.

Для одинаковых пикселей на всех машинах `uitest` включает светлую тему и рисует шрифты растеризатором nui (`NativeFontRendering = false`). Масштаб экрана задаётся через `uitest.SetScreen(w, h, scale)`; `scale` 2 даёт снимки как на Retina.

### Чем headless-режим отличается от настоящего окна

| Что | В headless | Почему так |
|---|---|---|
| Поток UI | тестовая горутина | `Invoke` из других горутин выполняется на `Settle` и после каждого действия |
| Таймеры | срабатывают только на `Tick`/`Wait` | иначе снимки зависели бы от времени, например от мигания курсора |
| `Exec()` | возвращается сразу | тест сам ведёт события |
| `ShowModal` | не блокирует ни на одной ОС | как на Windows и Linux. Модальное окно блокирует ввод в родителя: клики в родителя игнорируются |
| Всплывающие окна (меню, списки) | рисуются поверх формы, получают клики | — |
| Пункты списков ComboBox, строки Table и TreeView | нарисованы, а не являются виджетами, поэтому `Find` их не находит | выбирать клавишами или кликом в точку `uitest.At(w.Popup(), x, y)` |
| Буфер обмена | свой у процесса | `ui.ClipboardGetText()` в тесте читает то, что скопировало приложение |
| Файловые диалоги | сразу возвращают «отмена» | — |
| Печать, трей | принтеров нет, иконка в трее невидима | — |
| Перетаскивание файлов наружу | не начинается | — |

## regression: известные баги

Каждый баг из [production-readiness.md, §5](production-readiness.md) с воспроизводимым поведением имеет тест в [ui/regression/known_bugs_test.go](../ui/regression/known_bugs_test.go):

```go
knownBug(t, 4, clicks > 0, "the button in a disabled panel is clicked")
```

- **Баг на месте** — тест пропускается (`SKIP`) с номером бага. `go test ./...` остаётся зелёным.
- **Баг исправлен** — тест падает с сообщением «known bug #4 seems fixed: make this an ordinary test». Нужно убрать вызов `knownBug` и оставить проверку обычной: теперь она защищает от возврата бага.

Без теста остаются:
- #8 — лишняя раскладка в `Label.SetText`, это производительность, её покрывает `BenchmarkLabelSetText`;
- #9 — `SetAnchors`, пустая заглушка, проверяется по коду;
- #13 — блокирующий `ShowModal` на macOS, без настоящего окна не воспроизводится.

## check-clients.sh: соседние приложения

```
scripts/check-clients.sh                 # все модули рядом с nui, которые требуют nui
scripts/check-clients.sh ../altfm        # указанные
QUICK=1 scripts/check-clients.sh         # только сборка и vet, без тестов
```

Каждый клиент проверяется дважды:
- **pinned** — с версией nui из его `go.mod`;
- **local** — с текущей рабочей копией nui. Она подставляется через временный `go.work`, файлы клиентов не меняются.

Скрипт завершается с ошибкой, если клиент работал с pinned и сломался с local. Логи неудач с local сохраняются в `$TMPDIR/nui-clients`.

Скрипт запускается перед тем, как менять публичное API: так видно, кого из клиентов затронет изменение.
