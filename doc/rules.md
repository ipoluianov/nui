# Правила nui

Короткий свод правил, которые не видны из сигнатур, но нарушать которые нельзя. Документ для разработчика и для ИИ-ассистента, который пишет код на nui: прочитать перед первым изменением.

## Поток UI

- **Все формы и виджеты живут в одном потоке UI** — главном потоке программы, где `main` вызывает `form.Exec()`. Обработчики событий, сигналы, таймеры и отрисовка вызываются в нём, по одному, поэтому обработчик одной формы может свободно трогать виджеты другой.
- **Другие горутины виджеты не трогают.** Работу в поток UI передают через `ui.Invoke(f)` (вернуть сразу) или `ui.InvokeSync(f)` (дождаться). После `f` формы перерисовываются сами.
- **Перерисовку из горутины** без изменения виджетов запрашивают `widget.RequestRepaint()`: много запросов до кадра дают одну перерисовку.
- **Долгая работа** — `ui.RunAsync(owner, work, done)`: `work` в горутине с контекстом отмены (отменяется и при закрытии формы владельца) и отчётами о ходе, `done` в потоке UI. С диалогом прогресса — `ui.RunWithProgress`.
- **Команды** — `ui.Action`: одна команда в меню, на панели инструментов и на сочетании клавиш; доступность — `SetEnabledFunc`, без ручного обновления пунктов.

## Раскладка и перерисовка

- **Перерисовка автоматическая** после каждого обработчика, `Invoke` и таймера. Ручной `Form().Update()` нужен только для данных, которые виджет рисует сам в `OnPaint` (см. `Widget.Update()`).
- **Раскладка отложенная.** `AddWidget`, `RemoveWidget`, `SetVisible`, `SetMinSize`/`SetMaxSize` и смена текста `Label` сами её запрашивают. Форма раскладывается один раз: перед кадром, перед вводом или при первом запросе геометрии (`X()`, `Width()`, `MinWidth()`…), поэтому позиция, прочитанная сразу после изменения, уже верная. `Form.UpdateLayout()` нужен, только если минимальный размер своего виджета изменился так, что nui об этом не узнала.
- **Сетка.** `AddWidget(строка, столбец, w)` — сначала строка. Без растягиваемых виджетов лишнее место делится между строками, поэтому внизу формы ставят `AddVSpacer(n, 0)`, а справа в ряду — `AddHSpacer`. Растягиваемость задают `SetXExpandable`/`SetYExpandable`.
- **Несколько виджетов в одной ячейке** лежат друг на друге, как в Qt; щелчок получает добавленный последним.
- **Один виджет — один родитель.** `AddWidget` молча ничего не делает, если виджет уже в форме: чтобы перенести виджет, сначала `RemoveWidget`.
- **Размеры — в логических пикселях.** На экране с масштабом 2 (Retina, 200%) окно и виджеты рисуются вдвое плотнее, а координаты и размеры в коде остаются прежними. Масштаб берётся у системы: на Windows — у монитора, на macOS — Retina, на Linux — `Xft.dpi` / 96 (его выставляют GNOME и KDE) или `GDK_SCALE`. Переменная `NUI_SCALE` (например, `NUI_SCALE=1.5`) задаёт масштаб на Linux вручную.
- **`SetEnabled(false)` отключает виджет и всё, что в нём.** `Enabled()` учитывает родителей.

## События

Подробно — в [events.md](events.md).

- **Сигналы:** `w.OnКакоеТо.Connect(f)`. Обработчиков сколько угодно, данные приходят аргументом.
- **`On…Changed` срабатывает на любое изменение значения**, в том числе из кода (`SetText`, `SetChecked`, `SetSelectedIndex`…), и только если значение действительно изменилось.
- **`OnActivated` (и `OnTextEdited`) срабатывает только на действие пользователя.** Обработчик, который сам выставляет значение, на них себя не зовёт.
- **Сигналы ввода** (`OnKeyDown`, `OnMouseDown`…) приходят до собственной обработки виджета; `Handled = true` её отменяет.
- **Старые `SetOn…`** хранят один обработчик, и каждый вызов заменяет предыдущий. `CurrentEvent()` устарел.

## Окна и диалоги

- **`form.Show()` и `ShowModal(parent)` возвращаются сразу**, кроме `ShowModal` на macOS, который ждёт закрытия. Не пишите код, который после `ShowModal` читает результат: результат диалога приходит в обработчике. Свои диалоги строят на `ui.DialogContent` и `ShowDialog` ([dialog.md](ui/content/dialog.md)).
- **Модальное окно блокирует ввод в родителя**, пока не закроется.
- **`form.Close()` закрывает окно и освобождает его виджеты**; `form.OnClose` может не дать закрыть окно, которое закрывает пользователь (`RequestClose`).
- **Вопрос перед потерей данных** задают через `ShowQuestionMessageBoxYesNoCancel`: Esc и крестик в нём означают «отмена», а не «нет».
- **Файловые диалоги** (`form.ShowOpenFileDialog` и другие) отдают результат в обработчик.
- **Стандартные диалоги:** `ShowInputDialog`, `ShowProgressDialog`, `ShowAboutDialog`, вопросы `ShowQuestionMessageBox…` — тоже с результатом в обработчике.
- **Место и размер окна между запусками** — `form.RememberState(settings, key)`, одна копия приложения — `ui.AcquireSingleInstance`, вывести окно вперёд — `form.Activate()`.

## Текст

- **Позиции в тексте — в рунах**, не в байтах: `TextPos{Line, Col}` у `TextBox`, `PosAt`/`OffsetOf` для смещений в `Text()`. Перевод строки — одна руна `"\n"`.
- **`TextBox.SetText` начинает историю отмены заново.** Правку, которую пользователь сможет отменить, делают `InsertText` (после `SelectAllText` — замена всего текста).
- **`Canvas.DrawText` переносит строки по `"\n"` и `"\r\n"`.**
- **Ввод через IME** (китайский, японский, корейский): окно набора открывается у курсора TextBox. На Windows это работает всегда, на macOS тоже включено по умолчанию (`ui.UseMacInputMethod(false)` до показа форм выключает): там же акценты по удержанию клавиши, мёртвые клавиши и панель эмодзи. Вне полей ввода клавиши идут в форму как есть.
- **Шрифт виджета** — `SetFontFamily` (встроенные `ui.FontFamilySans`, `ui.FontFamilyMono` или имя системного шрифта), `SetFontSize`, `SetFontBold`, `SetFontItalic`. Строка семейства может нести стиль: `"jetbrainsmono:bold"`.

## Таймеры

- **`w.AddTimer(ms, f)`** — повторяющийся, первый раз на ближайшем такте. **`w.NewTimer(d, f)`** создаёт остановленный, **`w.AfterFunc(d, f)`** срабатывает один раз. Все возвращают `*ui.Timer` со `Start`/`Stop`.
- **Таймер работает, пока виджет в открытой форме.** Повторный `Start` отсчитывает интервал заново — это debounce ([timer.md](ui/content/timer.md)).
- **Опрашивать таймером** то, о чём есть сигнал (выделение, размер, тема), не нужно.

## Свой виджет

- **Встраивайте `ui.Widget`** (или `ui.Panel`, `ui.DialogContent`) и вызывайте `InitWidget()` в конструкторе. Интерфейс `ui.Widgeter` иначе не реализовать.
- **Рисование** — `SetOnPaint(func(cnv *ui.Canvas))`, ввод — сигналы базового виджета или `SetOnMouseDown`/`SetOnKeyDown`.
- **Переопределять можно только методы интерфейса `Widgeter`**: `ProcessPaint`, `ProcessKeyDown`, `MinWidth`, `MinHeight`, `XExpandable`, `ProcessPropChange` и другие. nui вызывает их через интерфейс. Метод `ui.Widget`, который вызывает другой метод `ui.Widget` изнутри, попадёт в базовую версию, а не в вашу: в Go нет виртуальных методов.
- **Свои сигналы** — поля `ui.Signal[T]`, вызов через `Emit`.
- **Сравнивайте виджеты по `Id()`**, а не по интерфейсным значениям: значение, полученное из базового `Widget`, может нести тип `*ui.Widget`, а не ваш.

## Тесты

- **Формы тестируют без дисплея** пакетом `ui/uitest`: щелчки, ввод, меню, диалоги, эталонные картинки ([testing.md](testing.md)).
- **В тестах время не идёт само:** таймеры срабатывают на `Tick`/`Wait`, отложенные `Invoke` — на `Settle` и после каждого действия.
